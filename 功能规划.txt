建议集成的通用服务
1. 消息通知中心（高优先级）
理由：评论回复、内容审核、附件购买、系统公告——几乎所有业务插件都需要向用户推送消息。如果每个插件自己实现，会导致通知渠道碎片化。

核心能力：

统一消息队列表（message），记录来源插件、目标用户（后台/前台）、已读状态
支持站内信 + 后续扩展邮件/短信渠道
插件通过宿主导出函数 XAdmin_SendNotification() 投递消息
前台/后台各自有消息列表和未读计数 API
为什么不能做插件：通知需要与前后台用户系统深度绑定，且是其他插件的基础依赖。



3. 验证码 / 安全网关（中优先级）
理由：登录防爆破、注册验证、前台投稿防刷——这是全局安全基础设施，不分业务。

核心能力：

登录失败次数限制 + IP 临时封禁
图形验证码 / 滑动验证（可配置）
API 请求频率限制（Rate Limiting）
全局 IP 黑白名单
为什么不能做插件：安全网关需要在路由鉴权之前执行，属于请求管道的早期拦截层，不能委托给插件。



4. 邮件/短信发送网关（中优先级）
理由：验证码、密码找回、通知推送都需要。如果每个插件自己对接第三方 SDK，会重复配置和代码。

核心能力：

统一的邮件/短信配置（SMTP、短信网关密钥等）存入全局配置
提供统一的 XAdmin_SendMail() / XAdmin_SendSMS() 宿主函数
发送队列 + 失败重试 + 发送日志
验证码生成、校验、过期管理作为一个子模块
为什么不能做插件：验证码系统与前台会员注册/登录流程强耦合，属于基础设施。
