# 评论能力包示例

## 1. 目标

本文档不是抽象规范，而是一个可落地的能力包样例。

目标：

- 演示评论能力包在能力包规范下应该长什么样
- 演示它如何被内容类型 DSL 引用
- 演示它如何在生成期和运行期分别工作

## 2. 能力包身份

建议：

- `packId`: `comment`
- `version`: `1.0.0`
- `provider`: `xadmin`
- `kind`: `content-capability-pack`

## 3. 目录示例

```text
hosts/xadmin/capability-pack/comment/
├─ pack.json
├─ config.defaults.json
├─ config.schema.json
├─ generator/
│  ├─ pack.json
│  ├─ schema/
│  ├─ dsl/
│  └─ migrations/
├─ template/
│  ├─ generated/
│  └─ fragments/
└─ docs/
```

## 4. `pack.json` 示例

```json
{
  "formatVersion": 1,
  "packId": "comment",
  "name": "comment",
  "title": "评论能力包",
  "version": "1.0.0",
  "provider": "xadmin",
  "kind": "content-capability-pack",
  "description": "为内容插件提供评论能力",
  "compatibility": {
    "contentSystem": ">=1.0.0 <2.0.0",
    "pluginApi": ">=3.0.0 <4.0.0"
  },
  "config": {
    "defaults": "config.defaults.json",
    "schema": "config.schema.json"
  },
  "generator": {
    "entry": "generator/pack.json"
  }
}
```

## 6. 配置 Schema 示例

`config.schema.json`：

```json
{
  "type": "object",
  "properties": {
    "enabled": { "type": "boolean", "default": true },
    "mode": {
      "type": "string",
      "enum": ["flat", "threaded"],
      "default": "flat"
    },
    "requireApproval": { "type": "boolean", "default": true },
    "allowGuest": { "type": "boolean", "default": false },
    "allowQuote": { "type": "boolean", "default": true },
    "maxDepth": { "type": "integer", "minimum": 1, "default": 1 },
    "deleteMode": {
      "type": "string",
      "enum": ["soft-delete", "hard-delete"],
      "default": "soft-delete"
    },
    "listPageSize": { "type": "integer", "minimum": 1, "maximum": 200, "default": 20 },
    "ui": {
      "type": "object",
      "properties": {
        "showAdminEntry": { "type": "boolean", "default": true },
        "showFrontendForm": { "type": "boolean", "default": true }
      }
    }
  }
}
```

## 7. 在内容类型 DSL 中的引用方式

内容类型 DSL 中的示例：

```json
{
  "capabilityPacks": {
    "comment": {
      "enabled": true,
      "version": "1.0.0",
      "config": {
        "mode": "threaded",
        "requireApproval": true,
        "allowGuest": false,
        "allowQuote": true,
        "maxDepth": 3
      }
    }
  }
}
```

## 8. 生成期职责

评论能力包在生成期建议负责：

- 注入评论表结构或评论服务接线
- 注入前台评论 API
- 注入后台审核 API
- 注入后台管理页片段
- 注入插件路由注册片段
- 注入评论配置到生成产物

## 9. 运行期职责

评论能力包在运行期可以有两种模式。

### 9.1 内嵌模式

生成出的内容插件直接带评论实现代码。

适合：

- 第一版快速落地
- 无外部评论服务依赖

### 9.2 共享服务模式

生成出的内容插件通过 service/hook 接入评论插件。

适合：

- 多个内容插件共享评论系统
- 评论能力需要统一升级

建议第一版先支持内嵌模式，同时为共享服务模式保留元数据和接线能力。

## 10. 数据结构建议

若评论使用独立表，建议至少包含：

- `id`
- `targetType`
- `targetId`
- `parentId`
- `quoteId`
- `authorType`
- `authorId`
- `authorName`
- `content`
- `status`
- `createTime`
- `updateTime`
- `isDelete`

其中：

- `targetType`
  建议使用内容插件内容实体标识
- `targetId`
  对应内容主键

## 11. 状态建议

评论状态第一版建议支持：

- `pending`
- `approved`
- `rejected`

如果需要兼容老系统，也可内部映射为整型状态码，但 DSL 和配置层建议使用语义化值。

## 12. 后台 UI 建议

评论能力包建议向内容插件注入：

- 评论列表页入口
- 评论审核页
- 评论删除操作
- 评论配置页

这些页面不应和内容主实体后台页强耦合在同一个大模板中。

## 13. 前台 API 建议

第一版至少支持：

- `GET /comments/list`
- `POST /comments/add`
- `POST /comments/delete`

如果启用审核：

- 新增评论默认进入 `pending`

如果启用访客评论：

- 需定义访客身份字段策略

## 14. 与共享评论插件的接线

如果未来使用共享评论插件，评论能力包应负责生成以下接线信息：

- 当前内容插件的 `targetType`
- 当前内容标题字段
- 当前内容可见性策略
- 当前内容删除策略

这样评论共享服务不需要知道内容系统内部的 DSL，只消费稳定接线信息。

## 15. 升级场景示例

### 15.1 从 `flat` 到 `threaded`

风险：

- 需要启用 `parentId`
- 需要调整前端展示和后台审核逻辑

处理建议：

- 作为半自动或高风险升级
- 由升级顾问提示用户确认

### 15.2 从内嵌模式切换到共享服务模式

风险：

- 数据归属变化
- 运行期协议变化

处理建议：

- 默认禁止自动切换
- 必须提供专门迁移器

## 16. 为什么评论不应是一个开关

评论不是“有或没有”的单一开关。

评论至少天然包含：

- 审核策略
- 嵌套策略
- 引用策略
- 匿名策略
- 删除策略
- 展示策略
- 后台管理策略

因此评论应是一个完整能力包，而不是 `enableComment = true/false`。

## 17. 第一版最小落地建议

第一版评论能力包建议只做：

- 内嵌模式
- 平铺评论和基础嵌套二选一
- 审核开关
- 访客开关
- 后台审核页
- 前台列表与提交 API

先不要做：

- 评论共享服务强依赖
- 复杂权限矩阵
- 多租户评论隔离
- 评论市场化单独升级

## 18. 最低实现要求

一个可用的评论能力包，第一版至少必须具备：

- `pack.json`
- `config.defaults.json`
- `config.schema.json`
- 评论 API 生成片段
- 评论后台页生成片段
- 评论数据迁移模板

没有这些，就还只是一个“评论开关”，不是能力包。
