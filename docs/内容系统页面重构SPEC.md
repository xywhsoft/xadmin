# 内容系统页面重构 SPEC

> 2026-05-01 补充：模型编辑页下一轮重构不再继续堆叠横向 Tab，而是升级为“建模工作台”。详细方案见 [内容模型编辑工作台重构方案](/D:/Git/x-admin/docs/内容模型编辑工作台重构方案.md)。本 SPEC 的后续执行应以“字段列表常驻、能力可视化装配、页面配置可视化、生成预检闭环、DSL 高级化”为新的验收方向。

## 1. 文档目标

本 SPEC 用于跟踪 `content-system` 插件与其受管生成插件的页面重构进度。

原则：

- 本文档是本轮页面重构的执行清单
- 每完成一项任务，直接在本文档中勾选
- 本轮优先解决信息架构与交互流程问题，不扩展无关新功能
- 重构过程中尽量复用现有 DSL、接口、生成逻辑与已有能力

## 2. 当前背景

当前版本已经完成并验证了以下基础链路：

- [x] 内容类型 DSL 保存链路可用
- [x] 内容类型修订保存可用
- [x] 受管插件生成可用
- [x] `cms.article` 受管插件可被插件系统正确发现
- [x] `cms.article` 受管插件可成功启用并出现在插件列表
- [x] 生成完成后支持刷新后台壳层/菜单
- [x] 受管插件管理页可正常打开

当前主要问题：

- `content-system` 页面把模型列表、DSL、设计器、修订、挂载等全部塞在单页中，信息密度过高
- 受管生成插件把内容列表、内容编辑、能力挂载、数据预览等混在一个页面中，任务边界不清晰
- 页面布局与后台现有模块风格不一致的部分虽已初步收敛，但整体信息架构仍不符合后台管理习惯

## 3. 重构目标

### 3.1 Content System

目标结构：

- 列表页：只负责查看与管理内容模型
- 编辑页：只负责编辑当前模型
- 编辑页内部通过 Tabs 拆分 DSL、字段、策略、挂载、修订等不同任务域

### 3.2 受管生成插件

目标结构：

- 内容管理页：只负责列表、筛选、进入记录
- 内容编辑页：只负责编辑单条记录
- 扩展挂载页：只负责能力挂载与注册表
- 后续再视实现范围决定是否拆出栏目管理、评论管理、设置页

## 4. 本轮范围

### 4.1 包含

- `content-system` 前端页面结构重组
- 受管插件模板前端页面结构重组
- 受管插件菜单组织方式调整
- 与页面结构直接相关的少量路由调整
- 与页面重构直接相关的文案、状态流、跳转逻辑修正

### 4.2 不包含

- 新 DSL 字段设计
- 新增 capability pack 能力
- 新增评论、栏目、SEO 等业务能力实现
- 与页面重构无关的后端数据结构改造
- 与页面重构无关的插件系统功能扩展

## 7. 当前推荐执行顺序

按收益与风险排序，建议执行顺序如下：

1. 先完成 `content-system` 的列表页与编辑页拆分
2. 再完成受管插件“内容管理页 / 内容编辑页”拆分
3. 最后把挂载工作区独立出去

原因：

- 先把生成器自身结构理顺，后续模板改造更清晰
- 先拆内容列表与内容编辑，可以立即解决“新建按钮无感”的核心交互问题
- 挂载页独立虽然重要，但可以在 CRUD 主链路稳定后再做

## 8. 验收标准

当以下条件全部成立时，本轮页面重构视为完成：

- `content-system` 不再以单页堆叠方式呈现所有功能
- 受管插件不再把内容列表、内容编辑、挂载配置塞在同一主视图
- 用户可以按照“列表 -> 编辑 -> 返回列表”的后台常规路径完成核心操作
- 页面主要文案与交互风格与后台整体习惯基本一致
- 不依赖人工刷新即可看到新生成的菜单或视图入口

## 10. 2026-05-01 修订：受管内容插件目录化

本节覆盖本文早期“受管插件可后续再视范围拆出栏目管理”的说法。栏目管理现在进入受管内容插件核心边界。

新的生成目标：

- 受管内容插件不再生成单个菜单项，而是生成一个目录菜单。
- 目录下固定生成三个 component 页面：栏目管理、文章列表、草稿箱。
- 文章列表和草稿箱必须拆成两个页面。
- 文章列表固定查询非草稿内容，不再放草稿状态下拉框。
- 草稿箱固定查询草稿内容，不再放草稿状态下拉框。
- 栏目管理属于当前受管内容插件，不走宿主全局栏目页面。

新的验收项：

- [ ] 生成插件注册父级目录菜单。
- [ ] 生成插件注册“栏目管理”子菜单。
- [ ] 生成插件注册“文章列表”子菜单。
- [ ] 生成插件注册“草稿箱”子菜单。
- [ ] 文章列表页面只显示 `is_draft = 0`。
- [ ] 草稿箱页面只显示 `is_draft = 1`。
- [ ] 两个列表页都移除顶部草稿切换下拉框。
- [ ] 栏目筛选只读取当前插件自己的栏目树。
- [ ] 所有 component 页面 DOM `id` 都使用 `Table_`、`Toolbar_`、`Search_`、`Tool_` 等前缀加 `Content_MakePlugin_<safe_xid>` 生成，不能出现重复 ID。
