# 内容模型编辑工作台重构方案

## 1. 目标

本方案用于重构 `content-system` 的模型编辑页面。

本次重构的目标不是新增生成器能力，而是在保持现有 DSL、接口、生成逻辑基本不变的前提下，把当前“多 Tab + 大量 JSON 文本框”的编辑方式改成更接近真实建模工作的工作台。

核心目标：

- 字段编辑必须始终看得到字段列表。
- 能力接入必须从手写 `capabilitySlots` JSON 改成可视化装配。
- 页面、展示、策略等常用配置必须尽量表单化、选择化、拖拽化。
- DSL 继续作为唯一真源，但默认退到高级模式。
- 保存、预检、生成必须形成清晰的闭环，让用户知道本次修改会影响什么。

## 2. 当前问题

当前模型编辑页主要问题不是单个控件不好用，而是整体流程不符合用户建模习惯。

### 2.1 页面结构问题

当前结构是：

```text
基础信息 / 基础与实体 / 分组与界面 / 能力与策略 / 字段设计 / DSL / 修订记录 / 升级顾问
```

问题：

- 横向 Tab 太多，但每个 Tab 缺少全局上下文。
- 用户切到字段设计时看不到完整模型结构。
- 用户切到能力与策略时不知道字段、页面、生成结果之间的关系。
- 修订、升级顾问和生成动作没有形成一个清晰的生成前检查流程。

### 2.2 字段编辑问题

字段是内容模型最核心的部分，但当前字段编辑像一个孤立表单。

问题：

- 字段列表不够突出，用户难以快速判断已经有哪些字段。
- 新建、编辑、排序、复制、删除字段之间没有形成连续操作。
- 字段是否出现在表单、列表、详情、搜索、筛选中不够直观。
- 字段和展示分组、列表列、详情布局之间割裂。

### 2.3 能力接入问题

当前能力接入主要依赖 `capability_slotsJson`。

问题：

- 用户必须理解 `serviceXid`、`mount.surface`、`mode`、`configSchema` 等协议字段。
- 看不到当前系统已发现哪些能力提供方。
- 看不到能力是否需要运行期插件。
- 看不到启用能力后会生成或影响哪些文件、路由、页面、SQL。
- 能力配置和发布策略混在一个 Tab 中，任务边界不清楚。

### 2.4 JSON 使用过多

当前页面里很多常用配置仍然要求直接编辑 JSON，例如：

- 展示分组 JSON
- 列表列 JSON
- 索引 JSON
- 能力槽位 JSON
- 元数据标签 JSON

这些配置可以在 DSL 中继续保持结构化，但在 UI 上不应该作为默认编辑方式。

## 3. 新的信息架构

模型编辑页应改为“建模工作台”。

推荐布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部状态栏：文章 cms.article | 修订 1 / 已应用 1 | 保存 预检 生成 │
├──────────────┬──────────────────────────────┬────────────────┤
│ 左侧模型结构  │ 中间主编辑区                   │ 右侧状态与影响   │
│              │                              │                │
│ 概览          │ 当前选中任务的表单/编辑器        │ 校验结果         │
│ 字段          │                              │ 生成影响         │
│ - title       │                              │ 依赖状态         │
│ - summary     │                              │ 修订摘要         │
│ - cover       │                              │                │
│ 页面          │                              │                │
│ 能力          │                              │                │
│ 策略          │                              │                │
│ 生成          │                              │                │
│ 高级          │                              │                │
└──────────────┴──────────────────────────────┴────────────────┘
```

### 3.1 顶部状态栏

顶部状态栏固定展示当前模型状态和主要动作。

内容：

- 模型标题
- `xid`
- 当前 revision
- 已应用 revision
- 受管插件 `xid`
- 当前是否有未保存改动

操作：

- 保存修订
- 生成预检
- 生成/重新生成受管插件
- 返回模型列表

### 3.2 左侧模型结构导航

左侧不只是导航，还应该是模型结构树。

建议结构：

```text
概览
字段
  title
  summary
  cover
  status
页面
  后台表单
  后台列表
  前台详情
能力
  评论
  分类
策略
生成
高级
```

字段节点应展示字段名、类型和关键标记，例如：

```text
title     文本   标题字段
summary   文本   列表/详情
cover     图片   封面字段
status    整数   状态字段
```

能力节点应展示启用状态，例如：

```text
评论      已启用
分类      未启用
SEO       未启用
```

### 3.3 中间主编辑区

中间主编辑区根据左侧选中项切换内容。

原则：

- 编辑字段时，左侧字段列表保持可见。
- 编辑能力时，能力列表和已装配能力保持可见。
- 编辑页面展示时，字段池、分组和目标区域保持可见。
- 尽量避免用户在多个 Tab 之间来回找上下文。

### 3.4 右侧状态与影响栏

右侧栏持续展示当前改动的结果。

内容：

- 当前表单校验结果
- 生成影响摘要
- 数据库迁移风险
- 依赖插件/provider 状态
- 当前 revision 与已应用 revision 的差异摘要

右侧栏不是说明文档，不放冗长教学文案，只展示状态和可操作问题。

## 4. 推荐导航分组

新的一级导航建议为：

```text
概览 / 字段 / 页面 / 能力 / 策略 / 生成 / 高级
```

### 4.1 概览

负责模型身份和实体基础配置。

字段：

- 标题
- `xid`
- `name`
- `namespace`
- 图标
- 描述
- 数据表
- 标题字段
- 状态字段
- slug 字段
- 摘要字段
- 封面字段
- 发布时间字段

### 4.2 字段

负责 `entity.fields`。

布局：

```text
左侧字段列表       右侧字段编辑
[+] 新建字段       字段名称
title              字段标题
summary            存储类型
cover              控件类型
status             所属分组
                   是否必填
                   表单/列表/详情
                   搜索/筛选/排序
                   默认值
                   高级属性
```

字段列表要求：

- 始终可见。
- 支持点击编辑。
- 支持拖拽排序。
- 支持复制字段。
- 支持删除确认。
- 展示字段是否进入表单、列表、详情。
- 展示字段是否是标题、状态、封面、摘要、发布时间等语义字段。

字段编辑要求：

- 常用字段用表单控件。
- `component.props` 进入“高级属性”折叠区。
- `list` 选项优先提供表格式编辑器，不默认要求手写 JSON。
- 只有复杂对象才进入高级 JSON。

### 4.3 页面

负责后台表单、后台列表、前台详情的展示配置。

建议拆成三个子区：

```text
后台表单
后台列表
前台详情
```

后台表单：

- 分组列表。
- 字段池。
- 字段拖入分组。
- 字段排序。
- 分组标题、说明、折叠状态。
- 字段宽度或 span。

后台列表：

- 列表列选择。
- 列宽。
- 是否可搜索。
- 是否可筛选。
- 是否可排序。
- 默认排序字段和方向。

前台详情：

- 标题字段。
- 摘要字段。
- 封面字段。
- 发布时间字段。
- 作者显示。
- 能力挂载区域预览，例如评论挂载在详情页底部。

### 4.4 能力

负责能力装配，不再和策略混在一起。

布局：

```text
可用能力
- 评论 comment-system
- 分类 category
- 标签 tag
- SEO
- 投稿 submission

已启用能力
- 评论
  Provider: comment-system
  挂载面: public.record-detail
  公开提交: 允许
  审核: 继承
```

能力卡片要求展示：

- 能力名称。
- 来源：内置能力包、第三方能力包、普通插件 provider。
- 支持的挂载面。
- 是否需要运行期插件。
- 是否会生成文件、路由、SQL、页面。
- provider 是否已发现。
- 当前配置是否有效。

能力配置使用抽屉或弹窗。

评论能力示例：

```text
评论能力配置

基础
- 启用状态
- 挂载位置：文章详情页 / 后台详情页
- 显示标题

发布
- 允许公开提交
- 是否需要审核
- 每页条数
- 排序方式

运行期接线
- Provider: comment-system
- 前台入口
- 后台入口
- contentPlugin 参数预览
- contentId 参数预览
```

高级 JSON 只作为折叠区保留。

### 4.5 策略

负责业务流程策略。

内容：

- 草稿是否启用。
- 草稿模式。
- 发布流程。
- 默认状态。
- 删除模式。
- 作者字段。
- 发布时间字段。
- 访问控制占位。

能力相关配置不要放在这里。

### 4.6 生成

负责保存、预检、修订和生成闭环。

内容：

- 当前 revision。
- 已应用 revision。
- 未保存改动。
- 生成预检。
- 升级顾问。
- 修订历史。
- 生成记录。

生成前必须能看到：

```text
将更新文件：
- generated/main.c
- generated/admin.html
- generated/public.html
- runtime/managed.json
- runtime/contracts.json

数据库影响：
- 无结构变更
- 或新增字段/索引/表

能力影响：
- 新增评论挂载槽 comments
- 依赖 comment-system provider
- provider 已发现 / 未发现
```

### 4.7 高级

负责原始 DSL 与诊断。

内容：

- DSL 只读预览。
- 解锁编辑。
- 格式化。
- 从 DSL 同步到可视化表单。
- 可视化表单写回 DSL。
- 原始 advisor 数据。
- 原始 contracts 数据。

默认不要把高级 DSL 作为主要编辑入口。

## 5. JSON 降级规则

保留 DSL，但降低 JSON 的默认暴露程度。

### 5.1 必须可视化的配置

以下配置必须提供可视化编辑：

- `entity.fields`
- 字段显示位置：表单、列表、详情。
- 字段排序。
- 展示分组。
- 列表列。
- 默认排序。
- 草稿开关。
- 发布流程。
- 删除模式。
- 能力启用/禁用。
- 能力 provider 选择。
- 能力挂载位置。
- 能力常用 options。

### 5.2 可保留高级 JSON 的配置

以下配置可以保留高级 JSON：

- 复杂 `component.props`。
- 临时未表单化的能力配置。
- 自定义索引。
- 非标准 provider 扩展字段。
- 诊断和调试数据。

高级 JSON 必须有：

- 格式化。
- 校验。
- 错误定位。
- 恢复上一次合法值。

## 6. 与现有 DSL 的兼容

第一步重构不要求立即修改生成器 DSL。

前端工作台可以继续写回现有结构：

- 字段编辑写回 `entity.fields`。
- 页面配置写回 `presentation` / `ui`。
- 策略写回 `coreFeatures` / `policies`。
- 能力配置先继续写回 `capabilitySlots`。
- 高级页继续编辑完整 DSL JSON。

也就是说，第一阶段实现目标是：

```text
可视化工作台 -> 现有 DSL -> 现有保存接口 -> 现有生成器
```

后续再考虑把 DSL 从 `capabilitySlots` 演进成更自然的：

```json
{
  "capabilities": {
    "comment": {
      "enabled": true,
      "provider": "comment-system",
      "mount": {
        "surface": "public.record-detail",
        "mode": "optional"
      },
      "options": {
        "threadTitle": "评论",
        "pageSize": 50,
        "allowPublicPost": true,
        "moderationMode": "inherit"
      }
    }
  }
}
```

## 8. 验收标准

满足以下条件时，本轮模型编辑页重构视为完成：

- 用户进入模型编辑页后，不需要打开 DSL 就能完成基础模型、字段、页面、策略、能力配置。
- 字段页始终能看到完整字段列表。
- 字段新增、编辑、删除、排序不依赖手写 JSON。
- 评论能力可以通过可视化配置接入，不需要手写 `capabilitySlots`。
- 页面展示配置至少覆盖表单分组、列表列、详情关键字段。
- 生成前能看到本次变更的文件、数据库、能力影响。
- 高级 DSL 仍可用，但不再是普通编辑路径。
- 保存和生成仍使用现有后端接口，生成结果与重构前兼容。
