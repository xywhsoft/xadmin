# 栏目系统设计方案

> 2026-05-09 修订：本文早期结论将栏目视为生成内容插件的核心组成部分。当前口径已调整：栏目应作为可选能力包 `content.category` 建设。栏目仍归属于当前内容插件，不做宿主级全局栏目表；但未启用 `content.category` 时，生成插件不应生成或加载栏目相关代码、路由、菜单和 schema。当前实现口径以 [路由动态化与 CMS 能力包建设 SPEC](./路由动态化与CMS能力包建设SPEC.md) 为准。

> 更新时间：2026-05-01
> 状态：已调整为“受管内容插件内置栏目”方案

## 1. 核心结论

栏目系统不再设计为宿主级全局 `category` 子系统。

新的边界是：

- `content-system` 只负责定义内容模型、生成受管内容插件、升级受管区域。
- 生成出来的每一个内容插件，都内置自己的栏目系统。
- 一个生成插件只承载一种内容模型，例如 `cms.article` 只承载文章。
- 栏目只归属于当前内容插件，不能在同一个栏目下混合创建不同内容模型的数据。

这样做是为了保留 xAdmin 当前“模型字段驱动实体表”的设计方向。不同文章类型如果共用栏目并混合入库，就只能把自定义字段塞进 JSON，查询、筛选、索引和权限都会退化；这不符合当前内容系统要通过实战项目倒逼结构化能力进步的目标。

## 2. 菜单结构

受管内容插件生成后，不再注册为一个单独菜单项，而是注册为一个目录。

```text
文章
├── 栏目管理
├── 文章列表
└── 草稿箱
```

其中“文章”来自内容模型标题，实际生成时应使用当前插件的 `identity.title`。

菜单规则：

- 父菜单：目录节点，不直接承载业务页面。
- 栏目管理：管理当前插件的栏目树。
- 文章列表：只显示非草稿内容，不再放“全部/草稿”下拉框。
- 草稿箱：只显示草稿内容，不再放“全部/草稿”下拉框。
- 三个子页面都使用 pearadmin component 加载，不使用 iframe。
- 每个页面内所有 DOM `id` 必须按插件 XID 生成唯一前缀，避免组件加载时发生重复 ID。

推荐 ID 规则：

```text
Table_Content_MakePlugin_<safe_xid>
Toolbar_Content_MakePlugin_<safe_xid>
Search_Content_MakePlugin_<safe_xid>
Tool_Content_MakePlugin_<safe_xid>
CategoryTree_Content_MakePlugin_<safe_xid>
CategoryForm_Content_MakePlugin_<safe_xid>
DraftTable_Content_MakePlugin_<safe_xid>
```

`<safe_xid>` 由插件 XID 转换得到，点号、横线和其他非字母数字字符统一转为下划线。

## 3. 数据边界

每个生成插件拥有自己的业务数据边界。

推荐第一版仍落在 xAdmin 主库中，但表名必须按插件生成，不能使用宿主全局栏目表。

示例：

```text
cms.article
├── cms_article_category
└── cms_article_content
```

如果当前生成器第一阶段仍固定使用 `content_item`，也必须把栏目表和内容表限定在该生成插件内部语义下，后续升级时再收敛到按插件命名的物理表。

## 4. 表结构

### 4.1 栏目表

```sql
CREATE TABLE cms_article_category (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    parent_id        INTEGER DEFAULT 0,
    title            TEXT NOT NULL,
    slug             TEXT NOT NULL,
    path             TEXT DEFAULT '',
    level            INTEGER DEFAULT 0,
    sort             INTEGER DEFAULT 0,
    status           INTEGER DEFAULT 1,
    seo_title        TEXT DEFAULT '',
    seo_keywords     TEXT DEFAULT '',
    seo_description  TEXT DEFAULT '',
    create_time      INTEGER DEFAULT 0,
    update_time      INTEGER DEFAULT 0,
    delete_time      INTEGER DEFAULT 0
);

CREATE INDEX idx_cms_article_category_parent_sort
    ON cms_article_category(parent_id, sort, id);

CREATE UNIQUE INDEX idx_cms_article_category_parent_slug
    ON cms_article_category(parent_id, slug)
    WHERE delete_time = 0;
```

字段说明：

- `parent_id`：父栏目 ID，`0` 表示顶级栏目。
- `slug`：同级唯一，用于前台路径。
- `path`：物化路径，例如 `/news/company/`，用于前台路由、缓存和快速筛选。
- `status`：栏目启用状态；停用栏目不影响已有内容保存，但前台默认不可见。
- `delete_time`：软删除时间。

### 4.2 内容表增加栏目字段

```sql
ALTER TABLE cms_article_content ADD COLUMN category_id INTEGER DEFAULT 0;

CREATE INDEX idx_cms_article_content_category_status
    ON cms_article_content(category_id, status, is_draft, delete_time);
```

规则：

- `category_id = 0` 表示未归类。
- 内容列表可以按 `category_id` 精确筛选。
- 如需包含子栏目，先由栏目表查出子树 ID，再拼接 `IN (...)`。
- 不允许跨插件引用栏目 ID。

## 5. 后台页面

### 5.1 栏目管理

页面职责：

- 展示栏目树形表格。
- 新增、编辑、删除、启用、停用栏目。
- 调整同级排序。
- 查看栏目下内容数量。

推荐工具栏：

- 添加栏目
- 刷新
- 展开全部
- 折叠全部

表格列：

- ID
- 栏目名称
- Slug
- 状态
- 内容数
- 排序
- 创建时间
- 操作

行操作：

- 添加子栏目
- 编辑
- 删除

### 5.2 文章列表

页面职责：

- 展示当前插件的已发布或待发布内容。
- 不显示草稿。
- 支持按栏目筛选。
- 支持标题、摘要、Slug 搜索。

工具栏：

- 新增内容
- 刷新
- 批量删除

行操作：

- 编辑
- 删除

### 5.3 草稿箱

页面职责：

- 只展示 `is_draft = 1` 的内容。
- 不再通过顶部下拉选择“草稿”。
- 支持继续编辑、发布、删除。

工具栏：

- 新增草稿
- 刷新
- 批量删除

行操作：

- 编辑
- 发布
- 删除

## 6. 后台路由

每个生成插件注册自己的路由族。

```text
/admin/view/plugin/<xid>/categories
/admin/view/plugin/<xid>/articles
/admin/view/plugin/<xid>/drafts

/admin/api/plugin/<xid>/category/list
/admin/api/plugin/<xid>/category/get
/admin/api/plugin/<xid>/category/save
/admin/api/plugin/<xid>/category/delete
/admin/api/plugin/<xid>/category/sort

/admin/api/plugin/<xid>/list
/admin/api/plugin/<xid>/drafts
/admin/api/plugin/<xid>/get
/admin/api/plugin/<xid>/save
/admin/api/plugin/<xid>/delete
/admin/api/plugin/<xid>/publish
```

列表 API 分工：

- `/list`：固定查询 `is_draft = 0`。
- `/drafts`：固定查询 `is_draft = 1`。
- 两者都可接收 `categoryId`、`keyword`、`page`、`limit`。
- 不再让前端传 `draft=all|0|1` 来切换页面语义。

## 7. 前台路由

前台路由也归属于当前内容插件。

建议第一版保持简单：

```text
/api/plugin/<xid>/categories
/api/plugin/<xid>/category?slug=<slug>
/api/plugin/<xid>/list?category=<slug>
/api/plugin/<xid>/detail?id=<id>
/api/plugin/<xid>/detail?slug=<slug>
```

如果后续要生成公开站点路径，可以由插件配置决定：

```text
/article/
/article/<category-path>/
/article/<category-path>/<slug>.html
```

路径归属必须仍然在当前插件内解析，不能交给宿主全局栏目路由猜测模型类型。

## 8. DSL 影响

栏目不再是外部能力包，而是内容插件的核心骨架能力。

建议在 `coreFeatures` 中表达：

```json
{
  "coreFeatures": {
    "adminCrud": true,
    "publicApi": true,
    "draft": true,
    "category": {
      "enabled": true,
      "mode": "tree",
      "required": false,
      "maxDepth": 5
    }
  }
}
```

字段语义中保留 `semantic: "category"`，但它只用于把表单字段映射到当前插件自己的 `category_id`，不能映射到宿主全局栏目。

## 9. 需要硬绑定的系统

以下系统必须和生成内容插件硬绑定，不能做成宿主全局共享业务表：

- 栏目系统：栏目树、栏目路径、栏目状态、栏目内容数都属于当前内容插件。
- 草稿与发布流：文章列表和草稿箱是同一插件内部的两个固定视图。
- 软删除与回收策略：删除行为必须和当前插件的数据表、索引、权限一致。
- 前台列表与详情路由：路径、Slug、栏目路径必须能定位到当前插件的数据表。
- 字段筛选与索引：自定义字段来自当前内容模型，不能跨模型混查。
- 权限数据域：栏目级权限、内容级权限必须先落在当前插件内，再考虑接入统一权限服务。

以下系统可以使用共享服务，但绑定键必须包含插件身份：

- 附件系统：可以共享存储，但引用键必须包含 `plugin_xid`、`record_id`、`field_name`。
- 评论系统：可以是独立评论服务，但 `target_type` 必须包含插件 XID 或插件命名空间。
- 标签系统：可以共享标签词典，但内容与标签关系表必须区分插件。
- 全文搜索：可以共享索引服务，但索引文档必须包含插件 XID、栏目 ID、内容 ID。
- 审计日志：可以共享日志服务，但日志主体必须包含插件 XID 和业务记录 ID。
- SEO 与站点地图：可以共享生成器，但数据来源和 URL 规则必须按插件分组。
- 静态缓存：可以共享缓存服务，但缓存 key 必须包含插件 XID、栏目路径和内容 ID。

## 10. 实施顺序

### Phase 1：生成菜单目录和页面边界

- 生成父级目录菜单。
- 生成“栏目管理 / 文章列表 / 草稿箱”三个 component 页面。
- 将文章列表和草稿箱拆分为独立页面。
- 删除文章列表顶部的草稿下拉框。

### Phase 2：栏目表与后台 API

- 生成插件内栏目表。
- 生成栏目 CRUD API。
- 生成栏目树形表格页面。
- 内容保存时支持 `category_id`。

### Phase 3：内容列表接入栏目

- 文章列表支持栏目筛选。
- 草稿箱支持栏目筛选。
- 内容编辑页增加栏目选择。
- 前台列表 API 支持栏目筛选。

### Phase 4：前台路径和扩展系统绑定

- 生成栏目路径。
- 生成前台栏目列表和详情路由。
- 为评论、附件、搜索、SEO 等系统补齐插件身份绑定规则。

## 11. 废弃旧方案

以下旧设计废弃：

- 宿主级全局 `category` 表。
- `/admin/category/*` 全局后台栏目 API。
- `/api/v1/category/*` 全局前台栏目 API。
- 栏目表通过 `modelName + modelNs` 绑定模型。
- 在一个栏目下混合多种内容模型。
- 旧口径曾废弃“把栏目作为可选能力包接入生成插件”。该废弃结论已在 2026-05-09 取消。

当前口径：栏目是 `content.category` 可选能力包，不再作为生成内容插件的强制核心组成部分。
