## 一、高危（建议立即修复）

### H1 存储型 XSS：前台会员可打后台管理员（前台→后台跨域攻击链）
- 位置：`route_http/api.h:353-361`（/api/v1/profile，任意登录会员可改）→ `route_http/member.h:195-224`（管理侧存储）→ `template/member/user_edit.html:24,52,58`（渲染 sink）
- 证据：`<input name="nickname" value="{{$nickname}}">` —— 模板引擎 `{{$var}}` 原样输出（全仓引擎不转义；仅 {{#form}} 块有 Form_BufferAppendEscaped）
- 影响：任意注册会员把 nickname 设为 `"><script>fetch('/admin/auth/user?id=1',{...})</script>`，超管打开会员编辑页即在管理源执行脚本（HttpOnly 不阻止同源请求自动带 cookie）→ 完整后台沦陷。管理员写入的用户名/角色名/菜单 title/href 同属未转义 sink（源为管理侧，风险等级低一档）。
- 建议：写通用 `Util_HtmlEscape`，在 MakePageWithTemplate 渲染前对全部字符串插值转义（或模板引擎默认转义、白名单放行富文本字段）。

### H2 垂直越权：设置文件读写接口无 authLevel 门槛
- 位置：`route_http/option_file.h:317-378`（GET/POST/PUT）
- 证据：GET 直接 `Option_LoadFile → OptionFile_ReplyData` 全量返回；对比 `route_http/option.h:55-70` 的 Request_Option 有 `iAuthLevelUser < iAuthLevelRequired → 拒绝` 检查
- 影响：仅持"设置管理"权限（authID 15）的低权管理员可读取 authLevel=200 的 global.json（含 cp_url 秘密入口、smtp_password 等全部配置），并可经 PUT 改写 —— /admin/option 专门构建的 authLevel 防线被同数据面的结构化接口整体绕过。
- 建议：Request_Option_File 的 GET/POST/PUT 补同款 authLevel 校验。

### H3 日志脱敏绕过：口令明文进日志表并可回看
- 位置：`route.h:36`（bMaskBody=false）+ `route_http/option_file.h:341-378` + `modules/logs.h:78`
- 证据：`AddStaticRouteHTTP("/admin/option/file", ..., false);` —— F2 脱敏路由清单只覆盖了 `/admin/option`（true），遗漏同数据面的 `/admin/option/file`；设置保存 UI（page/option/file_edit.html:596-617）回填当前值（含 smtp_password），PUT 体整包入库；`route_http/logs.h:53-54` 把 body 列原样回显
- 影响：任何能看系统日志的管理员可读取配置口令明文（横向信息泄露 + 审计留痕里的敏感凭据）。
- 建议：该路由注册改掩码（true），或保存前剥离 password 类字段值。

## 二、中危

### M1 远程进程崩溃（DoS）：7 个处理器 strlen(NULL)
- 位置：`route_http/auth.h` 588/615/855/886/1122/1156/1410（role/group/auth 的 add+put、uris 的 put，共 13 处 `strlen(name)`/`strlen(desc)`）
- 证据：`str name = ValueText(tblForm, "name");` 缺 key 返回 NULL，无判空直接 `sqlite3_bind_text(..., strlen(name), ...)`；同文件 user POST 判空、member.h 全部 `-1` 传参均安全——仅此 7 处遗漏
- 影响：持角色/权限管理权限者发 `{"desc":"x"}`（无 name）即空指针访问，业务区单线程 → 整个服务进程退出（崩溃 dump 会留档，但重启前全部不可用）。
- 建议：统一改 `-1, NULL` 传参（语义即 strlen）或补判空。

### M2 权限残留：改角色/用户组不撤销既有会话
- 位置：`route_http/auth.h:248-275`（user PUT 改 role/authLevel）、`route_http/member.h:195-224`（member PUT 改 groupId，仅 status==0 才撤销）
- 证据：UPDATE 成功后无 `Session_RevokeAccount`；会话内 roleID 是登录快照，Auth_ReloadCache（重建 role→URI 映射）救不了"用户换了角色"这一层
- 影响：被降权/换角色的账户，其在线会话继续以旧角色操作直至过期。对比 repwd/删除均正确撤销（R3/F1 已做）。
- 建议：role/groupId 变更成功后调用 Session_RevokeAccount（admin/member 两侧）。

### M3 自锁：删除超管/自身无保护
- 位置：`route_http/auth.h:277-293`
- 证据：`if (id > 0)` 即删——id=1（超管）与当前登录者自身均可删；对比 role 删除（auth.h:671）有 `id==1` 拒绝、group/auth 删除有 `id>1`——防御不一致
- 影响：管理员可删掉超管账号或自己 → 后台锁死需手工改库。
- 建议：补 `id==1` 与"当前会话 id"拒绝分支。

### M4 会话劫持面：trace 接口全量倾倒在线 XID 与全部配置
- 位置：`route_http/trace.h:104-132`（sessions dump）、`134-158`（option dump）
- 证据：`ValueSetOwn(tblData, "admin", G_AdminSessions)` —— 每个在线管理员的 XID + 身份全量返回；option dump 含 smtp_password/cp_url；该组 uris needLog=0 不留访问痕迹
- 影响：持"调试"权限（authID 20，默认仅超管角色）者可直接取任意在线 XID 充当 Cookie = 等效超管。默认权限配置下风险有限，故评中。
- 建议：生产构建禁用 trace 组，或对 xid/口令类值脱敏并将 needLog 置 1。

### M5 命令注入：filemanager 外部工具调用引号未转义
- 位置：`plugin/filemanager/main.c:913-924`（thumbnail magick）、compress/extract 的 7z/tar 命令（945-1110）
- 证据：`snprintf(sCmd, ..., "...magick \"%s\" ...", sPath); system(sCmd);` —— FM_IsPathSafe 允许文件名含 `"` `&` `|`，`a" & cmd & echo ".png` 即逃逸引号注入命令
- 影响：持文件管理权限者获得 OS 命令执行（文件系统模式下本已近 OS 权限，v1 同款行为，故评中）。附带：extract 的 Windows 分支 if/else 两臂完全相同（死分支）；解压依赖 7z/tar 自身的 ../ 防护。
- 建议：对进入命令行的路径做元字符拒绝/转义，或改 CreateProcess argv 数组传参。

### M6 设计面：免鉴权外部 API 无频控无长度上限
- 位置：`plugin/xlogserver/main.c:1046-1175`（/api/v1/log/push、/api/v1/task/create）；`plugin/guestbook_v3` 公开 add（转义已完备，仅无频控）
- 证据：push 的 class/text 长度不限、无 IP 频控；task/create 任意人可在任意服务下无限建任务行
- 影响：日志库/任务表灌水 DoS（磁盘与列表性能），属 v1 契约继承的设计缺口。
- 建议：外部 API 加每 IP 频控 + text 长度上限（如 64KB）+ 任务数上限。

### M7 所有权错配 + 泄漏：sched 导出
- 位置：`route_http/sched.h:17-18,44`
- 证据：`form = JsonParseN(...)` 永不释放（每次导出泄漏）；`keep = ValueGet(form,"ids")` 是**借用**引用却被直接 `xrtValueRelease(keep)`（当前"恰好"不崩是因为容器也泄漏——一改就炸的地雷）
- 建议：ValueGet 结果不可 release；form 用毕释放。

## 四、审计排除项（验证为干净的面）

- **SQL 注入**：全部用户可控字符串走 `sqlite3_bind_text` 绑定；动态拼接仅服务端生成值（xlog 表名恒为 `log_%lld`、内容系统标识符过 `Content_SpecIsValidIdent`/`Content_SanitizeSqlIdent` 白名单）。
- **路径穿越**：option 文件名双重白名单（`[A-Za-z0-9_-]+\.json`）；attachment 路径服务端生成（Util_Token+日期）；filemanager 全部 12 个文件操作口均过 `FM_IsPathSafe` + 上传 basename 净化（本轮已加固）。
- **XSS（客户端）**：guestbook 前台/管理页所有插值经 gbEscape/gaEscape；JSON 接口原样回显不构成执行面（真正的 sink 是服务端模板，见 H1）。
- **登录与会话**：XID 用 xrtSecureRandom（16 字节安全随机）；密码双哈希（客户端+服务端 salt）；暴破按 IP 锁定；会话存储 ValueSetText 为拷贝语义（无借用悬垂）；SESSION_PER_ACCOUNT=5 驱逐语义正确。
- **资源纪律**：全仓 JsonParseN 泄漏扫描仅 sched 1 处（M7）；stmt bind→step→reset 纪律整体良好；错误路径释放完整。
- **内容生成器**：标识符白名单 + C 字符串/SQL 标识符转义齐备，未见注入路径。
