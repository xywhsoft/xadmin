# 模型系统设计方案

## 1. 系统概述

模型系统是 x-admin 的核心功能模块，提供了一种**低代码**方式来快速创建和管理业务数据模型。通过模型系统，用户可以在后台界面定义数据结构，系统会自动生成：
- 数据库表结构
- CRUD API 接口
- 后台管理界面
- 前台投稿功能
- 评论系统
- 访问控制机制

### 1.1 设计目标

1. **零代码建模**：通过界面配置即可创建完整的数据模型
2. **运行时编译**：使用 TCC 编译器在运行时编译模型代码，无需重启服务
3. **功能可配置**：每个模型可独立启用/禁用各项功能
4. **自动化管理**：自动处理数据库迁移、路由注册、权限配置

### 1.2 技术架构

## 2. 核心概念

### 2.1 模型实例 (ModelInstance)

每个模型对应一个 `ModelInstance` 结构体，包含：

| 属性分类 | 字段 | 说明 |
|---------|------|------|
| **基础信息** | sName | 模型标识（英文，目录名） |
| | sTitle | 模型显示名称 |
| | sDesc | 模型描述 |
| | sNamespace | 命名空间（API路径前缀） |
| | sIcon | 图标 |
| | iSort | 排序值 |
| | sTableName | 数据表名 |
| **功能开关** | bEnableApi | 启用前台API |
| | bEnableAdmin | 启用后台管理 |
| | bEnableSubmit | 启用前台投稿 |
| | bEnableReply | 启用评论功能 |
| | bEnableAccessControl | 启用访问控制 |
| **状态** | bEnabled | 是否启用 |
| | bCompiled | 是否已编译 |
| | pTccState | TCC编译状态机 |

### 2.2 命名空间

命名空间用于组织和隔离不同业务领域的模型：
- API 路径格式：`/api/{namespace}/{model}/...`
- 后台路径格式：`/admin/{namespace}/{model}/...`
- 数据表名格式：`model_{namespace}_{name}`

**示例**：
- 命名空间 `cms`，模型 `article` → 表名 `model_cms_article`
- API 路径：`/api/cms/article/list`

### 2.3 字段系统

每个模型包含自定义字段列表，字段属性包括：

| 属性 | 说明 |
|-----|------|
| name | 字段名称（英文） |
| title | 显示名称 |
| type | 字段类型 |
| required | 是否必填 |
| defaultValue | 默认值 |
| showInList | 是否在列表显示 |
| desc | 字段描述 |

**支持的字段类型**：

| 类型 | 说明 | SQLite类型 |
|-----|------|-----------|
| text | 单行文本 | TEXT |
| textarea | 多行文本 | TEXT |
| richtext | 富文本编辑器 | TEXT |
| number | 数字 | INTEGER |
| switch | 开关 | INTEGER |
| select | 下拉选择 | TEXT |
| date | 日期 | INTEGER |
| datetime | 日期时间 | INTEGER |
| image | 图片 | TEXT |
| file | 文件 | TEXT |

## 3. 功能开关详解

### 3.1 前台 API (enableApi)

启用后自动生成以下 API 接口：

| 接口 | 方法 | 说明 |
|-----|------|------|
| `/api/{ns}/{model}/list` | GET | 分页获取列表 |
| `/api/{ns}/{model}/get/{id}` | GET | 获取详情 |

**权限控制**：
- `iApiAuthLevel`：访问所需的会员权限级别（0=游客可访问）

### 3.2 后台管理 (enableAdmin)

启用后自动生成以下功能：

| 接口 | 方法 | 说明 |
|-----|------|------|
| `/admin/api/{ns}/{model}/list` | GET | 后台列表 |
| `/admin/api/{ns}/{model}/get/{id}` | GET | 后台详情 |
| `/admin/api/{ns}/{model}/add` | POST | 添加记录 |
| `/admin/api/{ns}/{model}/put/{id}` | POST | 更新记录 |
| `/admin/api/{ns}/{model}/del/{id}` | POST | 删除记录 |

**自动注册**：
- 自动添加到后台菜单
- 自动创建权限组
- 自动注册 URI 到权限系统

### 3.3 前台投稿 (enableSubmit)

启用后允许前台会员提交内容：

| 接口 | 方法 | 说明 |
|-----|------|------|
| `/api/{ns}/{model}/submit` | POST | 投稿（保存到草稿） |
| `/api/{ns}/{model}/draft/list` | GET | 我的草稿列表 |
| `/api/{ns}/{model}/draft/get/{id}` | GET | 草稿详情 |
| `/api/{ns}/{model}/draft/put/{id}` | POST | 更新草稿 |
| `/api/{ns}/{model}/draft/del/{id}` | POST | 删除草稿 |
| `/api/{ns}/{model}/draft/publish/{id}` | POST | 发布草稿 |

**配置选项**：
- `bAllowGuestSubmit`：是否允许游客投稿
- `bSubmitNeedReview`：投稿是否需要审核

### 3.4 评论系统 (enableReply)

启用后自动生成评论功能：

| 接口 | 方法 | 说明 |
|-----|------|------|
| `/api/{ns}/{model}/{id}/reply/list` | GET | 评论列表 |
| `/api/{ns}/{model}/{id}/reply/add` | POST | 添加评论 |
| `/admin/api/{ns}/{model}/reply/del/{id}` | POST | 删除评论（后台） |

**配置选项**：
- `bReplyNeedApprove`：评论是否需要审核
- `iReplyAuthLevel`：评论所需权限级别
- `iReplyQuoteMaxLen`：引用摘要最大长度

### 3.5 访问控制 (enableAccessControl)

启用后支持内容的访问级别控制：

**系统字段**（自动添加到数据表）：
- `accessLevel`：访问级别（0=公开）
- `accessPrice`：付费价格
- `accessPreview`：预览内容

**配置选项**：
- `iDefaultAccessLevel`：默认访问级别
- `bEnablePreview`：启用预览功能
- `bEnablePurchase`：启用付费功能

**访问逻辑**：
1. 检查内容的 `accessLevel`
2. 比对用户的会员等级
3. 如果等级不足：返回预览内容或提示付费

## 4. 系统字段

每个模型数据表自动包含以下系统字段：

| 字段 | 类型 | 说明 |
|-----|------|------|
| id | INTEGER | 主键，自增 |
| createTime | INTEGER | 创建时间（时间戳） |
| updateTime | INTEGER | 更新时间（时间戳） |
| isDelete | INTEGER | 软删除标记（0/1） |
| authorType | INTEGER | 作者类型（0=系统, 1=管理员, 2=会员） |
| authorId | INTEGER | 作者ID |
| authorName | TEXT | 作者名称 |

**访问控制字段**（启用访问控制时）：
| 字段 | 类型 | 说明 |
|-----|------|------|
| accessLevel | INTEGER | 访问级别 |
| accessPrice | REAL | 付费价格 |
| accessPreview | TEXT | 预览内容 |

## 6. 数据库表结构

### 6.1 主表结构

表名：`model_{namespace}_{name}`

```sql
CREATE TABLE model_cms_article (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    -- 自定义字段
    title TEXT,
    content TEXT,
    -- 访问控制字段（可选）
    accessLevel INTEGER DEFAULT 0,
    accessPrice REAL DEFAULT 0,
    accessPreview TEXT,
    -- 作者信息
    authorType INTEGER DEFAULT 0,
    authorId INTEGER DEFAULT 0,
    authorName TEXT,
    -- 系统字段
    createTime INTEGER,
    updateTime INTEGER,
    isDelete INTEGER DEFAULT 0
);
```

### 6.2 草稿表结构

表名：`model_{namespace}_{name}_draft`

草稿表与主表结构相同，但不包含 `isDelete` 字段（使用硬删除）。

### 6.3 评论表

统一使用 `reply` 表存储所有模型的评论：

```sql
CREATE TABLE reply (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    modelName TEXT,        -- 所属模型名称
    contentId INTEGER,     -- 内容ID
    userId INTEGER,        -- 评论者ID
    userType INTEGER,      -- 用户类型
    content TEXT,          -- 评论内容
    quoteId INTEGER,       -- 引用评论ID
    quoteText TEXT,        -- 引用摘要
    status INTEGER,        -- 状态（审核等）
    createTime INTEGER,
    updateTime INTEGER,
    isDelete INTEGER DEFAULT 0
);
```

## 7. 运行流程

### 7.1 启动流程

```
1. 加载模型管理器 (ModelManager_Init)
   ↓
2. 扫描 script/model 目录
   ↓
3. 读取每个模型的 config.json
   ↓
4. 创建 ModelInstance 实例
   ↓
5. 检查已启用的模型 (status.enabled = true)
   ↓
6. 执行模型启用流程 (Model_Enable)
```

### 7.2 模型启用流程

```
1. 检查/创建数据库表 (Model_EnsureTable)
   ↓
2. 检查表结构变更，执行迁移 (Model_MigrateTable)
   ↓
3. 生成模型代码 (Model_GenerateCode)
   - 读取模板 model_code.tpl
   - 替换变量和条件块
   - 输出 code.h
   ↓
4. TCC 编译代码 (Model_Compile)
   - 创建 TCC 状态机
   - 编译 code.h
   - 链接到主程序
   ↓
5. 初始化模型 (Model_Init)
   - 传递全局数据（数据库连接等）
   - 初始化预编译语句
   ↓
6. 注册路由 (Model_RegisterRoutes)
   - 动态添加 HTTP 路由
   - 注册到权限系统
```

### 7.3 禁用流程

```
1. 调用模型清理函数 (Model_Cleanup)
   ↓
2. 移除所有注册的路由
   ↓
3. 释放 TCC 状态机
   ↓
4. 更新模型状态
```

## 8. 扩展机制

### 8.1 自定义字段类型

可在 `model_mgr.h` 中扩展字段类型：
1. 在 `Model_GenFieldReadCode` 等函数中添加类型处理
2. 在 `Model_GetSqliteType` 中定义 SQLite 类型映射

### 8.2 自定义 API

通过修改 `model_code.tpl` 模板添加自定义 API 逻辑。

### 8.3 钩子机制

未来计划支持：
- 数据保存前/后钩子
- 数据删除前/后钩子
- 访问控制自定义逻辑

## 9. 最佳实践

### 9.1 命名规范

- 模型名称：使用小写英文，如 `article`、`product`
- 命名空间：使用小写英文，如 `cms`、`shop`
- 字段名称：使用小写驼峰，如 `createTime`、`authorName`

### 9.2 性能优化

- 合理使用 `showInList` 控制列表查询字段
- 大文本字段（richtext）建议不在列表显示
- 适当使用索引提升查询性能

### 9.3 安全考虑

- 前台 API 权限级别应根据业务需求设置
- 敏感内容应启用访问控制
- 评论功能建议启用审核
